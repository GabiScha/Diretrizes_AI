# Manifesto de Aprendizado & Diretrizes de Uso de IA

Este repositório documenta a metodologia de estudo, os critérios de autoria e as diretrizes éticas e técnicas que aplico no desenvolvimento dos meus projetos de software durante minha graduação. Ele existe para garantir que o uso de Inteligência Artificial acelere minha produtividade **sem comprometer minha retenção de conhecimento orgânico e meu raciocínio crítico**.

## As 4 Regras de Desenvolvimento

### 1. Tentativa Primária

* **O Princípio:** Enfrentar o problema antes de buscar ajuda.

* **A Prática:** Diante de um erro ou bug, dedico tempo para analisar o sistema e tentar implementar a solução de forma autoral antes de consultar ferramentas externas.

### 2. Diálogo Socrático e Debate Arquitetural

* **O Princípio:** A IA atua como parceira de discussão, não como digitadora de código.

* **A Prática:** Utilizo a IA para debater ideias conceituais (como comparar estruturas de dados e padrões de projeto). A decisão final e a implementação são sempre minhas.

### 3. Retenção por Memória

* **O Princípio:** Entender a explicação não garante o aprendizado.

* **A Prática:** Após consultar uma explicação teórica, fecho o chat e escrevo o código baseando-me exclusivamente no meu raciocínio e memória.

### 4. Revisão do Código

* **O Princípio:** O código autoral deve ser testado sob perspectivas externas.

* **A Prática:** Escrevo a lógica principal do projeto e utilizo a IA ao final como revisora para identificar vulnerabilidades de segurança, gargalos de desempenho ou cenários de teste não cobertos.

## Diário de Bordo (`LOG.md`)

Todos os meus projetos principais possuem um arquivo `LOG.md` na raiz do repositório. Este arquivo funciona como um diário de desenvolvimento transparente, registrando:

1. **Evolução Diária:** Etapas concluídas e progresso da engenharia do software.

2. **Decisões Técnicas:** Por que determinadas estruturas e arquiteturas foram escolhidas.

3. **Registro de IA:** Descrição explicita de onde a IA foi consultada, quais dúvidas conceituais foram debatidas e como essas ideias foram aplicadas no código final.

## Matriz de Transparência de Autoria (`AI-DECLARATION`)

Em cada repositório, incluo uma matriz categorizando o nível de assistência computacional utilizado:

| Nível de Assistência | Descrição | 
| ----- | ----- | 
| **`None` (Totalmente Humano)** | Implementação de código autoral, regras de negócio, estruturas de dados e debates conceituais de arquitetura. | 
| **`Pair` (Par de Programação)** | Refatoração de sintaxe orientada, interpretação de erros complexos e auxílio em trechos pontuais. | 
| **`Auto` (Gerado/Auxiliado)** | Geração de dados simulados (mocks), documentação auxiliar ou autocomplete padrão de sintaxe. | 

> *"O software e as decisões são meus, a IA é apenas a ferramenta de diagnóstico e debate."*
